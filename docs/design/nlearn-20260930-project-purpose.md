# nlearn 项目目的与范围

日期：2026-09-30

## 项目目的

`nlearn` 是一套独立实现的张量计算与自动微分框架，提供熟悉的 PyTorch 风格 API。它有自己的张量、计算图、反向传播、神经网络模块、优化器和运行时实现；使用者可以直接检查并按具体需求修改这些实现。

项目希望同时做到三件事：在不依赖 PyTorch 运行时的前提下执行常见张量和训练工作流；用熟悉的接口降低迁移概念的成本；让核心组件易于理解、替换和扩展。配套书稿和教程承担教学价值，库本身的定位不局限于教学。

## 面向的人群

- 熟悉 PyTorch API、希望使用独立实现或裁剪运行时的开发者。
- 需要根据场景修改张量算子、后端或训练组件的研究者与工程师。
- 想通过可运行源码理解张量计算与自动微分机制的学习者。

## 项目价值

1. **独立运行**：张量、自动微分和训练组件由本项目实现；PyTorch 不作为运行后端。
2. **熟悉接口**：保留一部分 PyTorch 风格 API，便于用户沿用常见的张量和训练表达方式。
3. **可检查与修改**：核心路径由 Python、NumPy 和模块化算子组成，可按需求替换实现。
4. **可对照**：可在相同数据和参数下与 PyTorch 比较前向、梯度及参数更新，核对行为。

## 范围

- 使用 NumPy 实现 CPU 张量运算和自动微分。
- 提供基于 CuPy 的可选 CUDA 路径；具体环境支持以依赖和设备测试结果为准。
- 覆盖常见 Tensor、autograd、`nn`、优化器、数据加载和状态保存能力。
- 通过 MLP、CNN 和 Transformer 示例验证主要组件如何组合。
- 保持模块边界清楚，便于用户添加算子、调整组件或替换后端实现。

## 明确边界

- 不承诺完整实现 PyTorch API，也不承诺任意 PyTorch 脚本可以直接替换运行。
- 不以 PyTorch 训练性能、内存效率或完整生态兼容性作为目标。
- 示例运行成功只证明该示例覆盖的链路可用，不能推导出通用兼容。
- CUDA 是否可运行取决于 CuPy 与 CUDA 环境；未在具备设备的环境完成的路径应明确标注。

## 后续工作判断标准

新增工作应至少满足下列一项，并说明如何验证：

1. 提升张量、自动微分或训练组件的可用性与可扩展性。
2. 支持一个重要工作流，并同时核对前向与梯度行为。
3. 修复影响已承诺语义的正确性问题。

扩大 API 覆盖面时，应说明它服务的用户场景、实现边界和验证方式。维护时限制功能范围、减少重复实现，并保持关键运行路径清楚。
